# AiLGNS 观测站

链上原生观测站：**30/40/30 实际分配 · 每日结算 · 领取明细 · 资金全景 · 协议状态 · 推荐关系**。不依赖 ailgns.ai。

---

## 页面里有什么（两部分，更新方式不同）

| 区块 | 内容 | 更新方式 |
|---|---|---|
| **链上实时** | 公开买入开关（实时探测）· 当前区块 · AiLGNS/DAI 池现价 · 协议储备 | **每 30 秒自动刷新**，浏览器直读 Anubis 链 |
| **链上分配** | 30/40/30 实际分配、每日结算、领取地址与原始事件 | 由定时任务读取区块日志更新 |
| **资金全景** | 协议储备 / 主池 / 涡轮 / 手续费归集 的 DAI 余额 | **每 60 秒自动刷新**，浏览器直读 |
| **买算力流水** | 累计买算力金额、笔数、最近 24 小时 | 由定时任务更新（增量扫描）|

**「公开买入」这一栏是实时探测出来的**：页面直接去链上模拟一次买入，被拒绝就显示「未开放」，一旦通过就变绿并弹出提示。
这样即使你不在电脑前，只要页面开着，就能第一时间看到买入开放。

## 方式 A（推荐先用这个）：双击打开，零安装

直接双击文件夹里的 **index.html**，用浏览器打开就能看。

- **不需要安装任何东西**，不需要 Node.js，不需要开服务器
- 页面里内置了抓取当时的数据快照，标注为「数据源：内置快照」
- 双击打开时数据**不会自动更新**（浏览器安全限制，本地文件不能联网读同目录文件）

想看最新数据时，重新生成一次快照即可（见方式 B 或 C）。

---

## 方式 B：本机跑，实时更新

需要装 **Node.js 18 或更高版本**（https://nodejs.org/zh-cn ）。

装好后，在本文件夹里打开终端（Windows：在文件夹地址栏输入 cmd 回车），执行：

    node server.mjs

然后浏览器打开： **http://localhost:8787**

- 启动时会自动抓一次数据（此时页面会标注「数据源：实时」）
- 右上角「刷新」按钮点一下立刻重新抓
- 页面每 30 分钟自动重读一次

停止：在终端按 Ctrl + C。

> ⚠️ 如果提示「node 不是内部或外部命令」，说明还没装 Node.js，用方式 A 或方式 C。

## 方式 C：挂到 GitHub Pages（不用开电脑，手机随时看）

**这是唯一能“每天自动更新”的方案**：GitHub Actions 每 30 分钟自动采集一次。

### 第 1 步：建仓库并上传

> ⚠️ **最容易踩的坑**：拖拽时要**全选文件夹里的内容**（Ctrl+A），**不要拖整个文件夹**。
> 拖整个文件夹的话，网页会变成 `/仓库名/index.html`，打不开。

**怎么打开文件所在位置**：按 Win+R，粘贴下面这行，回车 ——

    D:\codex\2026-09-08\ni\outputs\ailgns-monitor

然后在文件夹里按 **Ctrl+A** 全选，把所有文件和 .github 文件夹一起拖到 GitHub 的上传框里。


把本文件夹里的所有内容传上去：`index.html`、`collect-chain.mjs`、`collect-levels.mjs`、`server.mjs`、`data.json`、`p-levels.json`、`README.md`，
以及 `.github/workflows/update.yml`、`.github/workflows/update-levels.yml`（这个文件夹默认隐藏，上传时要确认带上）。

### 第 2 步：开 Pages

仓库 → **Settings → Pages** → Source 选 **Deploy from a branch** → Branch 选 **main**、目录选 **/ (root)** → 保存。

等 1–2 分钟，地址是： https://你的用户名.github.io/仓库名/

### 第 3 步：允许机器人提交数据

仓库 → **Settings → Actions → General** → **Workflow permissions** → 选 **Read and write permissions** → 保存。

### 第 4 步：手动跑一次验证

仓库 → **Actions** → 左边选 `update-data` → 右边 **Run workflow**。

跑完回到 Pages 网址刷新即可。之后每 30 分钟自动运行一次。

> GitHub 定时任务高峰期可能延迟几分钟到几十分钟，属正常。

## 关于「最新一期」

官方是 **T+1 公布**：某一天的名单在**第二天凌晨约 02:58（UTC+8）**公布，公布后还有 24 小时挑战期才能领取。

所以页面上「最新一期」的日期通常比今天早 1–2 天，这是正常的，不是抓取失败。

---

## 抓取失败怎么办

- 采集器优先读取链上，失败时会沿用上一次成功的快照
- 链上事件解析规则集中在 `collect-chain.mjs`
- 终端里能看到具体失败原因

## 关注钱包（链上地址状态）

- 想盯哪些钱包，把地址**一行一个**写进仓库根目录的 `watchlist.txt`（`#` 开头是注释），提交后等下一次自动更新即可。
- 采集器直接读取每个地址的：登记算力、生效算力、直推地址数、推荐人、最新结算后的链上领取记录。
- 结果写进 `data.json` 的 `watch` 字段，页面「关注钱包 · 链上地址状态」一栏直接显示。
- 链上关系表不等于官方完整“三个区”业绩；P 等级仍要结合 veAiLGNS 门槛和官方规则确认。

## P1–P7 链上估算名单

- `collect-levels.mjs` 扫描 `PowerRecorded` 真实 DAI 投入事件，读取每个地址的上级链，汇总每条直推线的团队业绩。
- 单区门槛：P1 5 万、P2 15 万、P3 50 万、P4 150 万、P5 400 万 DAI。
- 同时读取 Ve 合约里的剩余锁仓本金，按协议价折算锁仓价值，再核对 P1–P7 的 ve 门槛。
- 官方“三个区”的后台划分没有公开，因此页面按每个地址最大的 3 条直推线估算；最终等级仍以官方 DApp 为准。
- 输出文件为 `p-levels.json`，每日由 `update-levels` 工作流更新，随后合并进 `data.json`。
## 极简查询页 check.html

- 打开 `/check.html`：输入钱包，直接扫描 Anubis 链上领取日志。
- 显示：个人算力兑付累计、社区动态奖励累计、合计，以及近期历史记录。
- 不连接钱包，不读取私钥，不依赖任何第三方整理站。

## 链上原生采集器

`collect-chain.mjs` 负责：

1. 通过 Anubis RPC 读取协议状态、算力、金库、池子、手续费等。
2. 通过区块浏览器原始日志解析每日结算、30/40/30 分配和领取事件。
3. 通过 `commRoot()` / `referrals()` 读取推荐关系。
4. 增量扫描 DAI Transfer 日志，统计用 DAI 参与算力的累计流水。
5. 写入 `data.json` 供 GitHub Pages 读取。

本地验证命令：

    node collect-chain.mjs
